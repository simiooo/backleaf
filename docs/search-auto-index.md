# 默认搜索自动使用持久索引（步骤 ①）

2026-11-06。目标：索引是加速器而不是第二套结果语义。默认搜索（`FileView.indexed == false`）在覆盖充分且索引健康时使用持久索引，否则静默回退实时目录扫描；用户看到的范围、筛选、排序与匹配规则不变，也不新增界面状态。

## 已实施

`search::scan` 在开始扫描前尝试以只读方式打开 `file-index.sqlite`（不存在或不可读时直接回退），再由 `index::plan_scope` 判定是否可用：

- 只考虑 `roots.building = 0`（构建完成）的根；
- 根路径本身不能位于 `problems`（不可访问）中；
- 当前文件夹必须落在某个已登记根内（组件级、大小写不敏感比较）；
- 当前文件夹必须已存在于索引：根按存储路径直接使用，子目录用文件身份匹配 `entries.identity` 取得索引中的实际路径拼写（避免依赖用户输入的大小写或 `\\?\` 前缀差异）；找不到就回退。

命中后，本次搜索只查询该根内的当前文件夹范围：递归搜索用 UTF-16 路径 BLOB 的区间条件覆盖整棵子树，非递归搜索用 `parent = 当前文件夹` 只取直接子项；不再把“当前路径搜索”扩大到所有索引根。显式 `FileView.indexed == true`（搜索弹层的“已索引位置”）保持原有跨全部索引根的全局语义。

查询策略：`grams` 支持任意 **2 字符对**（不限 CJK）与 1 个 CJK 字；≥3 字符走 FTS5 trigram；1 个非 CJK 字符仍走 `instr`。扩展 grams 对旧库由 writer 启动时一次性回填并置 `grams_v2`；读端在回填完成前仍按旧行为只用 CJK grams/`instr`，不会读到不完整结果。每个候选在写入本次临时结果库前仍核对当前文件身份，可见页仍逐项核验，正确性检查没有放宽（`modified` 秒数允许 ≤1 秒的目录项时间戳滞后，identity/bytes 仍精确）。核验按父目录分组：同一父目录达到 8 个候选时，用一次批量目录枚举（`GetFileInformationByHandleEx`）替代逐文件 `CreateFile`；不足 8 个或批量枚举不可用时回退逐文件 `identity::capture`。实测同目录 60 命中的首屏核验从 33.4 ms 降到 18.8 ms（1.78×），完成时间从 37.8 ms 降到 18.8 ms（2.01×）；该场景下索引路径相对实时扫描首屏 1.70×、完成 1.32×。2 字符查询（如 `ue`）相对旧的 `instr` 路径首屏 2.19×、完成 2.78×，相对实时扫描 2.8–3.7×；代价是构建 13.2→16.8 s、索引 29.5→40.6 MB。结果缓存命中且索引 revision 未变时跳过选择性预检。见[批量核验证据](evidence/search-auto-index/search-bulk-validation-20k.json)与[短查询 grams 证据](evidence/search-auto-index/search-short-grams-20k.json)。

范围查询不能把 SQLite 的计划交给“先扫当前子树、再逐行 MATCH”：实测 2 千文件时单批查询曾达 586 ms。现在范围查询用 `MATERIALIZED` 子查询先取倒排索引命中的 entry id，再按主键回表，并把范围条件放在外层；同样的查询降到约 3 ms。全局“已索引位置”仍走原来的连接形式。

由于每个候选仍要做身份核对，命中集很大时索引可能比实时扫描慢。规划器因此增加选择性保护：用 `index::scope_size` 与 `index::estimate_matches`（有上限的计数）估算匹配量，只有预计匹配数不超过“子树规模 / 24（夹在 96–4096 之间）”时才走索引，否则回退实时扫描；预检本身只读索引，开销约毫秒级。该保护只作用于自动模式，显式“已索引位置”不变。

`/24` 最初来自成本模型而不是实测最优。20,201 项的阈值扫描把单位成本拟合为：实时扫描约 11.4 µs/项、索引约 63 ms 固定开销 + 0.36 ms/候选，交叉点约在 `/46`。因此 `/8` 明显过激（2,000 命中实测比实时扫描慢 2.3 倍），`/64` 偏保守（放弃交叉点附近的收益），当前 `/24` 偏激进（500 命中实测 0.91×）。是否把默认系数调到 `/48`、以及 96/4,096 两个边界值的依据，还需要小文件夹和 10 万项大树的补充数据；本轮保留 `/24` 并记录数据，见[阈值敏感性证据](evidence/search-auto-index/match-budget-sweep-20k.json)。

结果缓存仍以完整 `FileView` 为键；`search_cache::Stamp` 区分文件系统与索引两种来源，同一查询在“路径扫描/索引范围”之间切换时会失配并重新执行，不会复用另一模式的结果。`IndexStatus` 的 revision 变化会在最近一次扫描确实使用索引时触发既有搜索刷新。

## 边界与未实施

- 没有通知排空屏障：索引写入线程应用目录通知有毫秒级延迟，刚创建的文件可能短暂缺项，靠 revision 变化后的搜索刷新收敛；下一步加“搜索前确认变更队列已排空”的水位。
- 宽匹配由选择性保护放回实时扫描，而不是改写成只核对可见页；真正的懒核对是后续可选优化。
- 未覆盖目录、根正在构建、根不可访问、索引缺失/损坏、以及未来 LRU 淘汰后的根，都回退实时扫描；回退不改变结果语义。
- 依赖当前目录已是索引目录项，因此重解析/云占位目录、被排除目录和索引刚登记尚未扫描到的目录会回退。
- 基准测出的两个开销待后续优化：暖查询仍重复做 open/规划/水位/选择性预检（约 31–45 ms，实时扫描暖命中约 10–25 ms）；精确/中等索引查询的首屏晚于实时扫描的首批流式结果。
- 本步骤不含按需扩容与 LRU 保护、空闲调度、休眠/卷恢复、损坏重建；它们属于后续步骤。

## 验证

- `index::tests::scoped_plan_uses_identity_and_keeps_queries_inside_the_covering_root`：根/子目录/非递归范围、根外回退、构建中与根不可访问拒绝、`scope_size`/`estimate_matches` 计数。
- `search::tests::default_search_uses_covered_index_scope_and_falls_back_outside_it`：默认搜索命中索引范围，未覆盖根回退实时扫描且结果一致。
- 无头回归 `headless_tests::automatic_search_uses_covered_index_and_falls_back_after_removal`：真实生产视图里默认搜索使用索引，移除索引根后仍通过实时扫描得到相同结果。
- 真实文件基准：20,000 文件/200 目录，精确文件名完成时间 65 ms 对实时扫描 227 ms（3.50×），200 命中前缀 114 ms 对 227 ms（1.99×）；宽匹配由选择性保护回退，未出现明显回退。方法与原始数据见[搜索自动使用索引性能测量](evidence/search-auto-index/README.md)。
- 按父目录批量核验：同一目录 60 命中的 A/B 基准首屏 33.4→18.8 ms（1.78×）、完成 37.8→18.8 ms（2.01×）；该场景索引相对实时扫描首屏 1.70×、完成 1.32×。测试开关仅用于基准 A/B，生产固定启用批量核验。
- 短查询 2-gram：2 字符查询相对旧 `instr` 路径首屏 2.19×、完成 2.78×，相对实时扫描完成 2.8–3.7×；旧库回填与回填前回退由 `index::tests::short_ascii_queries_use_extended_grams_and_migrate_legacy_rows` 覆盖。
- 全量门禁：fmt、严格 Clippy、逻辑/文件/COM 测试、生产 GPUI 无头交互、release 构建。
