# SIM-1007 · 搜索结果缓存

OpenPencil v43保留253页，新增重复查询、后台增量刷新和不可用状态。复用现有搜索输入、结果页、刷新交接和简短错误，不增加缓存提示、徽标或占位页面。先核对设计与独立冷重开，再实施。

缓存是每个搜索工作线程拥有的磁盘SQLite结果库，最多8个完整查询、合计128MiB、从查询开始起60秒；当前正在显示/构建的查询不属于可复用LRU预算。页面最多32行，排序与增量处理在后台，SQLite页缓存512KiB、排序可落磁盘。不在UI保留全量结果数组。缓存键包括无损UTF-16范围、大小写归一的字面查询、递归/索引模式、去重排序的扩展名集合、相对日期、大小、排序、方向、分组和布局。

普通路径搜索使用最多8个递归目录监听。监听就绪后才可缓存；变化、缓冲/队列溢出、重连、根身份变化或日期变化使该范围缓存失效，重新扫描。活动查询每250ms在后台检查通知并走现有保留旧页的刷新交接；没有通知时不反复发送进度。监听不可用时继续正常搜索，不把未就绪监听当可靠缓存依据。路径搜索排除自身结果缓存与既有Backleaf临时缓存。

索引搜索复用完整结果，并通过索引事务内的触发器记录受影响entry ID。日志最多8192条：插入、删除、身份/路径/名称变化和大小/修改时间变化参与；单纯扫描epoch更新不参与。重复查询没有索引变化时不再核查全部候选；有变化时只删除并重新判断受影响项，之后在磁盘重新排序/编号。重叠索引根保持路径去重，代表entry消失时寻找同路径的其他entry。水位缺口、数据库身份或根范围变化、重建、不可用位置及跨午夜使旧缓存失效。日志是Backleaf索引的失效记录，不能声称实现了NTFS USN离线追赶。

索引水位、范围和健康状态在短SQLite读事务内共同读取，构建完成还要核对水位未改变，避免把混合版本结果提升为完整缓存。遵循[SQLite隔离语义](https://www.sqlite.org/isolation.html)和[事务内触发器](https://www.sqlite.org/lang_createtrigger.html)。持久化索引仍使用WAL/NORMAL；可丢弃的结果库使用OFF事务日志，避免大结果排序建立内存回滚副本。结果取消、失败或不完整时直接丢弃，绝不复用中间库。

可见页另行验证当前文件：索引结果核对原身份、修改时间和大小；路径结果核对存在性、类型、筛选与所需排序元数据。替换或变化触发现有后台刷新，旧页继续显示到新页就绪。通知有异步延迟，搜索不是文件系统的全局原子快照；文件写操作仍要使用各自的冻结身份验证。

缓存仅跨当前进程中的查询复用，重启不复用结果；持久化元数据索引继续复用并后台校对。缓存目录为状态目录下search-results-v1，以独占owner.lock隔离窗口；新工作线程只回收已能取得所有权、无重解析点且文件类型符合预期的遗留session目录，保留其他正在使用的窗口。损坏缓存按未命中处理；缓存命中后发生查询错误时再以无该缓存的路径重试一次，真实搜索错误仍显示原有简短错误。

逻辑/真实文件测试覆盖冷热复用、插入/改名/删除、大小筛选、空结果变为非空、重叠根去重、日志截断、重建、同名替换、目录递归通知、LRU数量与字节预算、TTL、损坏缓存和独占遗留目录清理。生产GPUI无头用例覆盖复用、实际索引监听刷新、保留旧结果与滚动句柄；一并加入GitHub CI必需场景。性能数据与实际发布证据另记录确切源码，不把后台查询计时冒充输入到像素延迟。

SIM-1009补充：仅修改索引根的大小写也会改变SQLite中的原始路径与父目录键。索引写入器在事务内迁移到文件系统实际路径、清理旧键并重新建立该根；按路径更新监听，拒绝已删除根的迟到通知。启动时合并旧版本留下的同一实际根大小写别名，重新登记别名不增加第二个根。生产无头回归覆盖非递归搜索的恢复与后续新增；另有真实旧数据库重复根恢复测试。沿用v43的范围变化与重建交互，不增加界面状态。
