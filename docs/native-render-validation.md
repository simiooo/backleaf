# GPUI 原生渲染交付（SIM-951）

本单元以已接受的 OpenPencil v6 为基线，交付 Windows GPUI 原生可执行预览、真实目录分页、海量元数据虚拟网格、长文本与流光。搜索、索引常驻服务、Shell 文件写操作、完整 IME/拖放/屏幕阅读器验收继续按原事项推进，不将渲染样本进度当作真实复制。

当前渲染负载为文件图标与名称；系统图标提取、照片缩略图解码/回收及其 GPU 内存验证尚未加入，不能将这些图标网格的内存数值当作缩略图库的上限。

## 测量前确定的门槛

- 默认 1120 × 720 逻辑视口，持续滚动的场景 CPU P95 ≤ 8.33 ms，帧回调间隔 P95 ≤ 20 ms；宽窗 2200 × 1200 场景 CPU P95 ≤ 16.67 ms。P99、最大值和后台竞争一并保留。
- 百万项默认窗口峰值进程工作集 ≤ 384 MiB；1000、10万、100万、1000万项的显示缓存随视口增长，不随总项数增长。
- 每窗至多一个待执行帧回调；流光仅重绘最多 8 个可见名称，缓存固定文字布局，最多 60 次/秒。隐藏、收起、关闭、无活动项、减少动态效果时停止请求装饰性帧。
- 中文、组合字符、emoji/ZWJ、无空格长名称和长路径：网格两行省略、列表一行省略；完整值可在 tooltip/详情获取，详情可选择、复制，剪贴板与原始值相等。
- 支持百万/千万项末尾跳转、局部滚动、Ctrl+A 与单项排除。原生圆角、调整大小、最大化/还原、最小化和关闭需在 Windows 实测。

## 方法与边界

`cargo build --release --locked` 的实际 Windows 程序使用 GPUI 的 Win32、Direct3D 11、DirectWrite 后端。窗口始终由 GPUI 创建。`--fixture N` 是惰性生成的元数据压力样本，经过同一个真实网格与文字渲染路径，不创建 N 个磁盘文件，也不代表文件复制吞吐。`--path` 使用真实目录，由工作线程枚举到可丢弃的 SQLite 快照，再按主键范围分页到 UI。

场景 CPU 从视图开始构建到末端 canvas paint 记录；帧回调间隔反映原生场景绘制节奏，不能代替 GPU fence、屏幕呈现或输入到光子延迟。输入延迟从原生事件处理器开始到场景绘制。首次 1 秒的字体/设备初始化不计分位数，峰值内存和总 CPU 仍包含启动。静止且无重绘时样本为 0，不能写成“0 ms 帧时间”。

网格是独立的缓存 GPUI 视图，文件变更、选区与滚动才使其失效；流光视图独立更新。局部列表最多 4096 行，使用整数全局行锚点与局部子行偏移重定位，避免把千万项总高度装进 f32 滚动偏移。完整 UTF-16 文件名保存在快照中，显示字符串转换不会替换后续系统路径使用的原值。详情结果带视图代次与请求令牌；旧目录/旧文件响应不能覆盖新视图。

运行 `scripts/native/benchmark.ps1` 生成原始 JSON。脚本逐项检查 Windows 会话，并拒绝锁屏、断开的会话以及中途锁定的结果。`--session-status-file <json>` 只读取会话状态。原生应用使用本会话的 WTS 消息通知，锁屏时停止装饰性帧、解锁后恢复，既不解锁系统，也不改动锁屏设置。通知 API 与状态定义见 [Microsoft 会话通知](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/nf-wtsapi32-wtsregistersessionnotification)、[SessionFlags](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/ns-wtsapi32-wtsinfoex_level1_w)。

GPUI 的单行尺寸测量回调只返回固定几何，不允许它淘汰真实视口的数据页。名称只让最多 96 个字素进入网格塑形，再使用 GPUI 的 Unicode 换行/省略，完整名称仍在 tooltip/详情和可访问名称中。最终字形布局按可见范围缓存。当前固定 GPUI 版本的缓存视图复用路径没有同步复用 UIA 子树，因此辅助技术激活时保留完整可见树的渲染路径，仍复用文字布局，且不创建全部文件的节点。

减少动态效果的 CLI 分支只验证应用分支；系统设置通知、Narrator/NVDA、不同物理 DPI 和显卡兼容性须分别验证，不能由本机一次测试推断。宽窗请求为 2200 × 1200，当前桌面将实际客户区限制为 2048 × 1104；原始报告保留实际尺寸和 125% 缩放，不称作 4K 实测。
