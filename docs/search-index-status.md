# 搜索与索引现状 · 2026-11-05

对应 SIM-920 / SIM-922，应用测试包 0.1.0-preview.15，源码 786c6e53。此次是源码核对，未将未实现能力标为交付。

已实施：SQLite WAL 持久化元数据索引（file-index.sqlite）、Windows 递归目录通知驱动的增量插入/更新/删除、通知溢出后的重新校对、索引 revision 变化触发已打开索引搜索的重新执行。中文一、二字由 grams 表检索，三字以上走 FTS5 trigram；其他一、二字符使用字符串匹配。首次构建及恢复校对在后台进行，结果可按页显示。

输入采用250ms防抖，查询 token 使旧请求取消且不覆盖新结果；候选分批256项，UI每页最多32项。搜索中间结果及待扫描目录落临时SQLite，不在UI内存保存整棵目录树。每次索引查询仍核对候选文件的当前身份，避免旧索引结果直接作用于已被替换的文件。普通当前路径搜索与显式索引搜索是不同执行路径，并非所有搜索都走全局索引。

尚未实施跨查询的结果缓存：每次查询创建临时结果库；同词再次搜索、从其他查询切回时会重做查询。SQLite页缓存、目录/渲染缓存与这一能力不同。目前索引 revision 变化使当前索引搜索整体重跑，还没有只更新受影响缓存结果的策略。应用取得索引写锁后会对已登记根目录安排后台完整校对，复用持久化库而非丢弃重建，但还不是启动时只追赶离线增量日志。

后续若补齐缓存，需单独验证：规范化查询及筛选/排序/范围的缓存键，索引 revision 与文件身份的失效边界，有界LRU/磁盘预算，冷热与重复查询性能，离线变更、目录改名/删除、监听溢出及崩溃恢复下的一致性。不能把当前功能描述为已完成这组优化。

定位：src/index.rs、src/index_watch.rs、src/search.rs、src/app_search.rs、src/main.rs 的 IndexStatus 分支。现有测试覆盖中文短查询/trigram及增量改名删除；无头回归覆盖实际搜索输入、中文结果和防抖取消。
