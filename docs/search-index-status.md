# 搜索与索引现状 · 2026-11-05

对应 SIM-920 / SIM-922，应用测试包 0.1.0-preview.15，源码 786c6e53。历史核对基线；SIM-1007增补见下文，实际发布证据随测试包记录。

已实施：SQLite WAL 持久化元数据索引（file-index.sqlite）、Windows 递归目录通知驱动的增量插入/更新/删除、通知溢出后的重新校对、索引 revision 变化触发已打开索引搜索的重新执行。中文一、二字由 grams 表检索，三字以上走 FTS5 trigram；其他一、二字符使用字符串匹配。首次构建及恢复校对在后台进行，结果可按页显示。

输入采用250ms防抖，查询 token 使旧请求取消且不覆盖新结果；候选分批256项，UI每页最多32项。搜索中间结果及待扫描目录落临时SQLite，不在UI内存保存整棵目录树。索引查询未命中缓存时核对候选文件的当前身份；缓存可见页另行验证身份，避免旧索引结果直接作用于已被替换的文件。普通当前路径搜索与显式索引搜索是不同执行路径，并非所有搜索都走全局索引。

SIM-1007已补齐跨查询的有界磁盘结果缓存：普通路径搜索按递归通知失效，已索引搜索按事务变更ID增量更新；失败/取消/未完成结果不缓存，缺口/重建/离线/日期变化安全回退。细节、限制与验证范围见[缓存设计](search-cache-v43.md)。缓存仅跨本进程查询复用，重启继续复用持久化索引并校对，尚不是USN离线增量追赶。

定位：src/index.rs、src/index_watch.rs、src/search.rs、src/app_search.rs、src/main.rs 的 IndexStatus 分支。现有测试覆盖中文短查询/trigram及增量改名删除；无头回归覆盖实际搜索输入、中文结果和防抖取消。
