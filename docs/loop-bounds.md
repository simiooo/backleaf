# 循环、重试与递归边界

本项目要求所有长循环、自动重试与递归遍历都有明确的退出条件或上限；不允许“错误消失后自然结束”的隐式假设。本次权限重开修复中发现的目录监听循环就是反例：通知句柄持续失败时，周期身份探测每 2 秒把目录标脏，触发了无用户操作的后台刷新。

## 规则

1. **长驻循环必须有主动退出条件**：`stop` 原子标志、channel 关闭、generation/token 失配、用户取消或进程退出；仅当应用/服务仍存活且任务有效时循环才继续。
2. **自动重试必须有上限或改为用户触发**：失败不能无限轮询。目录加载/刷新失败后立即挂起该目录监听；通知句柄最多连续重连 15 次（约 28 秒），仍失败则发一次刷新事件并退出监听线程；后续是否重建由刷新结果决定。
3. **轮询必须有间隔与截止条件**：测试/基准中的等待都带 deadline；UNC 通知不可靠时的低频率轮询是显式的，频率固定为 2 秒，且随导航/窗口生命周期结束。
4. **递归与遍历必须有数量/深度/字节限制**：目录快照、搜索、索引和 ZIP 解包都限制条目数、字节数或深度；`-Recurse` 前拒绝 junction/symlink。
5. **重试动作必须是幂等或一次性**：提权 handoff 请求是一次性 JSON；UAC 一次；操作失败重试由用户按钮触发，不自动重放。

## 主要循环清单

| 位置 | 退出/上限 |
| --- | --- |
| GPUI 事件循环、窗口渲染 | 进程/窗口生命周期 |
| `navigation.rs` 路径解析 worker | `stop` 标志、请求 token |
| `app_watch.rs` 目录监听与自动刷新 | `Monitor` drop、加载失败 `suspend_watch()`、用户提示/右键/F5 触发单次重试、成功后重建 |
| `watcher.rs` `FindFirstChangeNotificationW` 重连 | 连续失败 15 次后发送一次 dirty 并退出；UNC 2 秒显式轮询 |
| `search.rs` / `index.rs` / `index_bulk.rs` 扫描 | `stop`/token/generation、条目/字节/时间预算 |
| `jump_list.rs` 重建 worker | pending 合并；每组条目上限 10/10/8/8；一次请求一次构建 |
| `operations/service.rs` 文件任务 | 任务完成/失败即终止；失败重试仅用户触发，上限由 ledger 失败根部决定 |
| 安装器/卸载器下载与解压 | 直链 + API 各一次回退；ZIP 条目/解压大小限制；目录递归前检查 reparse point |
| 测试与基准等待 | 全部带 deadline 的 `loop { if Instant::now() >= deadline { panic } }` |

新增后台循环或重试逻辑时，必须在 PR/提交说明中写清退出条件，并优先用可注入的 deadline/计数在测试中覆盖。
