# 受保护位置的提权检测与管理员窗口

2026-11-09。说明 Backleaf 在普通权限下遇到受保护文件夹时如何提示、如何以管理员身份重开同一位置，以及管理员权限在什么范围内有效。

## 背景

Backleaf 以普通用户权限运行（清单 `asInvoker`）。Windows 的部分位置不允许普通权限枚举，例如 `C:\System Volume Information`、`C:\Config.Msi`、`C:\Recovery`，以及其他用户的目录。对这些位置做目录枚举会得到 `ERROR_ACCESS_DENIED`（HRESULT `0x80070005`）。

旧行为只把这一错误作为一行状态文字显示在底部状态栏：文件区是空白，用户容易以为“点了没反应”。本版本把这个错误改成可操作的入口：明确告诉用户需要管理员权限，并允许在管理员窗口里重开同一位置。

## 交互流程

### 1. 访问被拒绝时提示

目录加载（首次导航到某位置、以及刷新）因权限问题失败时，界面出现模态提示：

- 标题为“需要管理员权限”，正文说明“此位置需要管理员权限才能访问。Windows 会请求你的同意，并在新窗口中以管理员身份打开同一位置。”；
- 列出失败的目标路径；
- 提供“以管理员身份重新打开”和“取消”两个动作。

提示是模态的，不会在用户不知情时自动提权。选择“取消”只关闭提示，当前窗口保持原样，用户可以再次导航或刷新后重试。

### 2. 一次 handoff 与 UAC 提权

用户确认后，主进程生成**一次性** handoff JSON，写入：

```text
%LOCALAPPDATA%\Backleaf\operations\elevation\
```

handoff 携带重开窗口所需的状态：目标路径、窗口位置/是否最大化，以及可用时的搜索定义、选区路径与滚动行。目录加载失败时搜索框已经关闭，因此常规提权入口只携带位置、窗口几何与当时仍有效的选区/滚动。handoff 只描述一个位置，不包含命令或脚本。

主进程随后用 `ShellExecuteExW("runas")` 启动同一可执行文件，参数为 `--elevate-request <json>`，并附带 `--state-dir`。UAC 由 Windows 弹出：

- 用户同意：系统创建新的管理员进程，原窗口保留；
- 用户取消（或 UAC 被拒绝）：原窗口的提示保留，可以重试。

### 3. 管理员窗口

管理员进程启动后：

- 读取 handoff 文件并立即删除，避免同一请求被重复消费；
- 按 handoff 恢复路径、窗口几何与可用时的选区/滚动，在相同位置打开新窗口；
- 该窗口的目录加载从被拒绝的位置开始，即自动重试。

原普通窗口保持不动，仅显示“已打开管理员窗口”，不改变其权限状态。管理员窗口是完整的 Backleaf 实例，与普通实例共享窗口状态数据库（新窗口有自己的窗口 id）、索引（第二个进程只读）与文件操作门控。

### 4. 管理员提示条

管理员窗口顶部常驻一条可关闭的提示条：“管理员权限已开启 · 关闭窗口后权限结束”。用户手动以管理员身份启动 Backleaf 时同样显示该提示条，避免用户忘记当前窗口权限高于平时。

关闭提示条只隐藏提示，不改变权限；权限随进程结束（见下节）。

## 权限持续语义

Windows 的提权是“每进程令牌”：管理员权限在进程创建时由 UAC 授予，无法追加给已经运行的普通进程，也没有 TTL 延长或刷新机制。

因此本实现：

- **不**常驻隐藏的提权代理进程；
- 权限只在管理员窗口/进程存活期间有效，存活时间不设上限；
- 关闭该管理员窗口（进程退出）即结束权限，之后如需提权重新从提示进入；
- 不把管理员权限“借用”给原普通窗口，原窗口始终按原令牌运行。

## 限制与边界

- 目前只覆盖“目录枚举/刷新被拒绝”这一个入口。文件操作结果面板内的批量失败、双击交给系统打开文件等场景仍按原错误展示，不自动提权重试。
- handoff 只包含一个位置；每次提权只重开这一个位置，不迁移浏览历史或其他窗口状态。
- 选区最多恢复 4096 项；超过该数量则不恢复选区（路径与窗口几何仍恢复）。滚动位置按行恢复。
- 管理员窗口与普通窗口共享状态库和索引，但它们是两个进程；管理员窗口关闭后，普通窗口仍是普通权限，受保护位置仍不可枚举。
- 提示只在权限错误导致目录加载失败时出现；其他错误（路径不存在、磁盘离线等）不走提权流程。

## 安全边界

- handoff 文件写在当前用户的状态目录内，由本机同一用户的中等完整性（普通权限）进程写入，管理员进程读取后立即删除。
- handoff 内容只表达“打开某个文件夹”和窗口状态，不包含可执行命令、脚本或任意 INI/注册表写入。
- 管理员进程校验 handoff 的版本与字段；文件缺失、非法或不兼容时不会执行任何提权请求，而是回退为普通窗口并给出提示。
- 路径按无损方式序列化与还原，避免转义导致打开错误位置；目标路径在管理员窗口中只作为“要打开的目录”，不改变其内容。

## 验证

- 无头回归覆盖：访问被拒绝时提示出现与取消、handoff 序列化与无损路径、管理员窗口按相同状态（位置/搜索/几何）恢复。
- 无头回归不触发真实的 `runas` 与 UAC，因此不会在 CI 中创建管理员进程。
- 真实 `runas` 与 UAC 交互依赖 Windows 桌面和用户账户控制，需要在实机上人工验证；本仓库 CI 不模拟 UAC，不把“自动测试通过”等同于提权链路的真实验证完成。
